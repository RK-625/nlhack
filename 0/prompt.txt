  ## Pending approvals are now dropped when the user sends a new message
  
  Sending a new user message in a thread with an unanswered approval now clears that approval and deletes its suspended run before the new turn streams. The write tool never runs. I checked this through the real `handleChat` path with a mock model. Nothing is committed (HEAD 50414d4), and I spawned no subagents.
  
  **How it works:**
  - **Server (`src/chat-api.ts`):** `handleChat` calls a new `dropPendingApprovals(agentId, user)` in its `last.role === "user"` branch. It reads the caller's own thread (via `ownThread`), finds assistant messages that still have `metadata.pendingToolApprovals`, and does two things:
    - **(a) Clears the stored approvals.** It uses `getStore("memory").updateMessages` on the storage store. The higher-level `MastraMemory` type has no `updateMessages`, so it can't be called there. LibSQL merges metadata keys on update rather than replacing them, so the key is set to `undefined` (dropped when saved) instead of deleted.
    - **(b) Deletes the suspended run's snapshot.** It calls `getStore("workflows").deleteWorkflowRunById` for `"agentic-loop"` and `"executionWorkflow"`, which are the rows Mastra itself deletes when an agent run finishes. That is a public storage API, so (b) is implemented, not skipped.
  - **Helper (`src/chat-approvals.ts`):** a new pure function `withoutPendingApprovals(messages)` returns the cleared `{ id, content }` updates plus the run ids, reusing `pendingApprovalIds`.
  - **UI:**
    - **Before a reload:** the old message keeps its approval card, which already shows "Not run: no decision was made."
    - **After a reload:** the dropped call comes back as an `input-available` tool part, which used to render as a step stuck on "running". `MessageBubble` now takes an `earlier` prop, which `MessageList` sets to `index < messages.length - 1`. In earlier messages, "running" steps are shown with the existing "declined" status.
    - **Why `earlier` and not `!streaming`:** it avoids briefly flashing "declined" on the latest message right after the user clicks Approve.
