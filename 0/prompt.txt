The rail and the expanded panel are two separate layers. When you toggle or snap, the code changes `compact` in React state right away, starts a width animation, and fades one layer out while the other fades in. Both layers are mounted at the same time only during that fade (`DURATION.fast`, 0.15s). There is no `LayoutGroup` anywhere, but `domMax` is loaded, so `layout` and `layoutId` already work.

### 6. Drag/snap flow and when the layers swap

- **`setMode(nextCompact, how)`** (L72-76):
  ```ts
  if (nextCompact === compactRef.current) return;
  commit(widthRef.current, nextCompact);   // setCompact → React re-render → layer swap starts NOW
  animateSize(nextCompact ? SIDEBAR.RAIL : widthRef.current,
              how === "snap" ? SPRING_SNAP : sidebarResize(!nextCompact));
  ```
  The layer swap happens immediately, at the start of the width animation: `compact` flips in the same tick that `animate(size, …)` starts. The crossfade (0.15s) runs alongside the width tween (0.3s) or the snap spring. The new layer is fully visible about halfway through the width change.
- **What triggers it:**
  - `toggle()` (L77): the Collapse/Expand buttons, double-click on the handle (L213), and Enter/Space (L136-139).
  - Arrow keys at the bounds (L145-151), using `"toggle"`.
  - Pointer drag (L104-126):

    - From expanded: going below `SNAP_TO_RAIL` (200) calls `setMode(true, "snap")` and restores `origin` as the remembered width.
    - Otherwise `size.jump(clampWidth(candidate))`, so the width follows the pointer 1:1 and holds at MIN (240).
    - After a snap, pointer moves are ignored for 180ms (`settleUntil`).
- `endDrag` (L128-133) commits the final width; that only re-renders, it doesn't swap layers.
- With reduced motion, `size.jump` runs instead of `animate`, but the opacity crossfade still plays.

### 7. Things that complicate a shared-`layoutId` avatar morph (rail ↔ expanded)

1. **Clipping:**
   - The `absolute inset-0 overflow-hidden` wrapper (Sidebar.tsx:168) clips anything that flies outside the aside's animating width.
   - Each panel's `nav` is `rk-scroll overflow-y-auto overflow-x-hidden` (L204, L437). Scroll containers clip the moving element, and Motion's layout measurement needs `layoutScroll` on scrollable ancestors to account for scroll offset; neither nav has it.
   - The aside's own width is animating while the avatars would morph. The rail layer is a fixed 76px, but the expanded layer is ≥240px and clipped by the aside, so expanded-avatar positions measured at mount are relative to a container that is still resizing.
2. **Both layers are mounted together during the swap** (sync `AnimatePresence`), and each layer is fading with `panelSwap` opacity. A `layoutId` pair would crossfade between the exiting copy and the entering copy, but the parent opacity fades multiply on top of it. The layers are absolutely overlapped at `start-0`, which helps.
3. **Size mismatch:**
   - Rail avatars are 40, the featured avatar is 56, specialist avatars are 36.
   - `agentAvatarValue` always returns `hex::shape_n`, so `BotAvatar` always takes the shape branch (bot-avatar.tsx:190-260). That branch renders a container `div` with `width/height: size`, a ring `&lt;svg&gt;` at `inset:-4` with `size+8`, and the main `&lt;svg width={size} height={size}&gt;`.
   - A `layoutId` morph between different sizes would scale-transform a fixed-pixel SVG. A 40→56 scale would look slightly soft, and drop-shadow filters and the ring would scale too.
   - The main SVG also has its own `transition-transform duration-300 hover:scale-[1.03]`, and `animate-pulse scale-[1.04]` when working (L240-246). Those CSS transforms are on a child, so they don't conflict directly, but they add movement.
4. **The tooltip wraps the rail item:** the Base UI trigger is the `button` itself, so the `m.span` around the avatar sits directly inside the button with no extra wrapper. That's fine for `layoutId`. A tooltip open at swap time would be left floating while the rail unmounts.
5. **Badges are siblings of the avatar,** absolutely positioned inside `AgentAvatar`'s `relative` span. They would move with that span if the `layoutId` goes on it, and scale with it. Specialist rows use `activityOnly`, so their badge set differs from the rail's: the unread badge disappears and the inline dot appears.
6. **Transforms and layout animation on ancestors:**
   - The rail avatar's wrapper `m.span` already has `variants={itemVariants}` (a `y` transform) and the staggered entrance.
   - Expanded items are `m.button`s with `itemVariants`; the specialist rows and the featured wrapper are `layout="position"`.
   - Putting `layoutId` on an element that is already a variants target is workable, but the `y` offsets on first load would mix with the morph.
7. **Featured tile filtering:** while a search filters out the assistant, the featured tile, and so its 56px avatar, is not rendered at all. That leaves no shared target for it. The rail ignores search entirely.
8. **Reduced motion:** `MotionConfig reducedMotion="user"` (main.tsx:24) turns off layout and transform animations, so the morph would become an instant swap with the opacity crossfade kept. `DockedSidebar` separately jumps the width (`useReducedMotion`, L42/L64). `BotAvatar`'s own CSS animations are off under `motion-reduce` and styles/ui.css:519-523.
9. **Remount on every swap:** each panel is fully remounted (keyed `rail` / `expanded`). ### Part 1 — Critique of the draft (what the Motion source shows)

**Step 1: `LayoutGroup` isn't needed. Keep the shared `layoutId`s.**
- Shared nodes are registered on the global projection root (`root.registerSharedNode`), so handoff works without a group.
- Both layers are children of `DockedSidebar`, so they re-render in the same commit anyway.
- `LayoutGroup` only adds cross-member re-measuring. That has a cost here because rows re-render on every streamed token.
- Still prefix the ids (`sidebar-avatar-…`, `sidebar-selected`), because the namespace is global.
- Unifying the highlight into one `sidebar-selected` is a good idea. It also fixes the current tile↔row selection, which jumps today because the tile uses a CSS class instead of a shared element.

**Step 1/2: drop `AnimatePresence` around the layers. Don't add `popLayout` or `presenceAffectsLayout`.**
- If the exiting layer is kept, handoff still works: the new node is promoted on mount and `stack.promote` takes `prevLead.snapshot`. But two things go wrong:
  - **Duplicate avatars.** With the default `crossfade: true`, both copies stay visible and crossfade. The old copy sits inside the old nav's clip, so it gets cut off.
  - **Removal and fades break.** The featured tile, rows and their labels sit inside the nested `AnimatePresence initial={stagger}`. `PresenceContext` is provided per `PresenceChild` (`PresenceChild.mjs`), so those nodes never see `isPresent=false`. Their `exit` animations never run, and the outer layer's removal time depends on whatever happens to subscribe.
- `popLayout` is irrelevant because the layers are absolutely positioned. `presenceAffectsLayout` only matters inside a `LayoutGroup`.
- The fix is two phases plus a plain conditional render. Fade the outgoing labels out *while that layer is still mounted*, then flip. At the flip, the outgoing layer holds only invisible labels and shared nodes, so unmounting it right away is invisible.
- Unmount-then-mount handoff is the same pattern `rail-selected` already uses. `unmount()` calls `willUpdate()` (snapshot) while the DOM is still attached, and `stack.lead` still points to the old node when the new one promotes. No duplicates, no crossfade, nothing to hide.

**Step 2: labels can't use `exit` or `initial="hidden"`. They must be driven by state.**
- Inside the nested `AnimatePresence initial={false}`, `PresenceContext.initial === false` reaches every descendant (`use-visual-state.mjs`: `isInitialAnimationBlocked`).
- So use `initial={false}` with `animate={chrome ? "visible" : "hidden"}`, reading the flag from a context. Consumers inside the frozen exiting subtree still get context updates.
- The existing `fade` token is exactly the label variant: fast duration, `EASE_EXIT` going out, `EASE_ENTER` coming in. No new tokens are needed.

**Step 3: the sequencing has a trap.**
- `animate(size, …).then()` never resolves if the animation is stopped. `JSAnimation.stop()` tears down without calling `notifyFinished`.
- That happens on a drag snap followed by continued dragging, because `size.jump()` stops the tween. The labels would stay hidden for good.
- Use `onComplete` and `onStop` together, gated by a run id.
- For the phase-1 wait, use Motion's frame-synced `delay(cb, ms)`, which returns a cancel function and is exported from `motion/react`.

**Step 4: the "≥240 clamp keeps targets stable" reasoning is wrong in two ways.**
- **The tile target drifts.** `panelWidth = max(size, 240)` grows 240→284 during an expand, but only after about 79% of the tween. The tile is `justify-center`, so its true center moves 120→142 late in the animation. Motion measured the target once at the flip, so the visible path gets a late kink. Collapse has no kink, so the two paths are not symmetric.
  - Fix: set the expanded layer's width to the target width at the flip, using an explicit `panelWidth` motion value.
