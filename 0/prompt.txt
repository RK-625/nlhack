  ### Risks and unknowns
  1. **Agent key vs id mismatch.** Registry keys `marketResearcher` / `cfoAgent` differ from ids `market-researcher` / `cfo`. `handleChatStream`'s `agentId` resolution (getAgent by key or getAgentById) isn't documented clearly. Test both in S3, or make keys and ids match.
  2. **No Mastra Memory.** History lives only on the client and is lost on refresh. The full history is sent every turn, which costs more tokens on long chats. Persisting it needs a storage adapter (LibSQL etc.).
  3. **Chat-route tracing.** The `wrapMastra` spans should still be emitted, but they will sit outside a `web.request` parent unless we wrap the route ourselves (Option A).
  4. **Visual fidelity.** Fidelity depends on keeping the arbitrary-value classes (`text-[15.5px]`, `rounded-[26px]`) and the token CSS exactly. `bot-avatar.tsx` uses `useSyncExternalStore` motion sync. Test reduced-motion.
  5. **Version alignment.** `chatRoute`/`handleChatStream` default to the v5 contract; we must pass `version: 'v7'` to match ai@7 / @ai-sdk/react@4. React 19.2.3 is within @ai-sdk/react's peer range.
  6. **CORS / ports.** In dev the web app is on :5173 and the server on :3000. Use the Vite proxy so no CORS is needed. In prod, serve the build from the same server.
  7. **Tooling.** Rakazo pins TypeScript 7.0.2; our repo uses TS 6. Use our TS version in `web/`. Small typing fixes may be needed.
  8. **Security.** The chat endpoint is public behind the ngrok tunnel with no auth. Add a simple shared token, or keep it local-only until auth exists.
