  - `LocalFilesystem` writes real files under `basePath` on disk, so they survive restarts. The workspace itself is stateless; only the files and any search index matter.
  - The files are persistent. The BM25 index is in memory (I assume, not confirmed) and is rebuilt from `autoIndexPaths` on init.
  - Per-user scoping works through the filesystem resolver, which runs on every tool call:
  ```ts
  const workspace = new Workspace({
    filesystem: ({ requestContext }) => {
      const uid = requestContext.get("userId"); // must exist and be sanitized
      return new LocalFilesystem({ basePath: join(dataDir(), "files", uid), contained: true });
    },
    tools: { [WORKSPACE_TOOLS.FILESYSTEM.DELETE]: { requireApproval: true } },
  });
  ```

  - Vector or hybrid search needs both `vectorStore` and `embedder`.
  - Per-user indexing is the weak spot (see above).
  - A simpler retrieval option is `list_files` plus `grep` plus `read_file`, which need no indexing and work with a per-user resolver.

  - A custom `createTool` pair (save and read) that writes to `${DATA_DIR}/files/<userId>/` or to libsql gives full control and explicit userId handling.
  - It would also avoid exposing generic fs tools such as edit and ast_edit. It is more code to write.
  - Memory working memory and semantic recall store notes and facts, not files, so they are not a real substitute.

  - Use Workspace with a resolver-based `LocalFilesystem` under `join(dataDir(), "files", userId)`, with `contained: true`.
  - Set the userId in the RequestContext in chat-api.ts.
  - Attach it per agent, only to the agents that save and read documents (for example the contract and assistant agents), rather than globally. Use an agent-level `workspace: ({requestContext}) => ...` or a shared instance.
  - Allow `list_files`, `read_file`, `write_file`, `grep` and `file_stat`. Disable `ast_edit` and `edit_file`. Require approval on `delete` only, matching the app's existing approval pattern. Plain writes can go through without approval, since they are scoped to the user's own folder.
  - Skip BM25 at first and use grep and list.
  - Sanitize `userId` before using it in the path, because the resolver builds the path from it.
